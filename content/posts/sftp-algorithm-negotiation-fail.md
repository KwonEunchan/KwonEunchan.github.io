## 문제 상황

개발 서버를 AWS 환경으로 이관하였으나, 기존에 정상 동작하던 SFTP 연계가 실패하는 현상이 발생했습니다.
아직 이관 전인 운영 서버에서는 특이사항이 없었습니다.

OS 설정부터 소스 코드까지 개발기와 운영기가 동일한 상태였음에도 AWS 환경으로 이관한 개발기에서만 연결에 실패하고 있었으며, 오류 내용을 보면 연결 과정 중 알고리즘 협상 단계에서 실패하는 것으로 보였습니다.

## 원인 분석

SFTP 연계는 JSch 라이브러리( 0.1.53 )를 사용하도록 구현되어 있었으며, 연결 시 아래와 같은 오류가 발생하고 있었습니다.

* `Algorithm negotiation fail`

처음에는 키 교환 알고리즘이 맞지 않는 것으로 의심하였으나, 클라이언트와 서버 모두 동일한 키 교환 알고리즘 목록을 등록하였음에도 마찬가지로 실패했습니다.
등록된 키 교환 알고리즘 중 하나라도 일치하면 해당 알고리즘으로 수행이 되어야 하는 만큼, 키 교환 알고리즘 자체의 문제는 아닌 것으로 판단했습니다.

이에 위 오류가 어떤 경우에 출력되는지 추가로 확인해 보았습니다.

* SSH는 연결 초기에 키 교환, 호스트 키, 암호화, 메시지 인증(MAC) 알고리즘을 각각 협상함
* 이 중 하나라도 클라이언트와 서버 간에 일치하는 알고리즘이 없으면 JSch에서는 동일하게 `Algorithm negotiation fail`을 출력함
* 즉, 키 교환 알고리즘 불일치 이외에 메시지 인증(MAC) 알고리즘이 맞지 않는 경우에도 위 오류가 출력됨을 검증함

실제로 OpenSSL 버전에 따라서는 서버에 MAC이 별도로 등록되어 있지 않으면 연결에 실패할 수 있음을 확인할 수 있었습니다.
AWS 환경의 OpenSSL 버전을 확인해 보니 기존 서버 대비 상위 버전이었으며, 서버에서 기본으로 허용하는 MAC 목록에 JSch 0.1.53이 지원하는 MAC이 포함되어 있지 않았던 것으로 보입니다.

결국 키 교환 단계가 아닌 MAC 협상 단계에서 일치하는 알고리즘이 없어 연결에 실패한 상황이었습니다.

## 해결 방법

서버 측 `sshd_config`에 JSch 0.1.53 버전에서 지원하는 MAC 알고리즘을 등록한 후 sshd를 재기동했습니다.

```text
# /etc/ssh/sshd_config
MACs hmac-sha2-256,hmac-sha2-512,hmac-sha1
```

* 기존에 허용하던 MAC 목록은 그대로 유지하고, JSch에서 지원하는 hmac-sha1을 추가하는 방식으로 적용함
* 설정 변경 후에는 `sshd -t`로 문법 오류가 없는지 확인한 뒤 재기동하는 것이 좋음

## 결과

MAC 등록 이후 SFTP 연계가 정상적으로 연결되었습니다.

다만 hmac-sha1은 비교적 오래된 알고리즘인 만큼, 서버의 보안 정책이 강화되면 같은 현상이 다시 발생할 수 있을 듯합니다.
장기적으로는 서버 설정을 낮추기보다 JSch 버전을 업그레이드하여 상위 알고리즘을 지원하도록 하는 방안도 검토가 필요할 것 같습니다.

## 배운 점

`Algorithm negotiation fail`이라는 메시지만 보면 키 교환 알고리즘 문제로 생각하기 쉬운데, 실제로는 키 교환 이외의 알고리즘 협상에서 실패해도 같은 메시지가 출력될 수 있었습니다.

앞으로 동일한 오류를 마주하게 된다면 키 교환뿐만 아니라 호스트 키, 암호화, MAC 알고리즘까지 클라이언트와 서버 양쪽의 지원 목록을 함께 비교해 볼 필요가 있을 것 같습니다.
또한 서버 이관 시에는 소스나 설정이 동일하더라도 OS와 라이브러리 버전 차이로 기본값이 달라질 수 있다는 점을 염두에 두어야 할 듯합니다.

요즘 온프레미스 환경에서 AWS로 마이그레이션하는 기업이 많아지고 있는데, AWS에서 기본으로 제공하는 OS 이미지는 기존 서버 대비 버전이 높은 경우가 대부분입니다.
OS 버전이 올라가면 OpenSSL, OpenSSH 등 보안 관련 패키지도 함께 올라가면서 오래된 알고리즘이 기본 허용 목록에서 빠지는 경우가 많기 때문에, 이번처럼 기존에 문제없이 동작하던 연계가 이관 후에 실패하는 일은 앞으로도 종종 마주하게 될 것 같습니다.
그런 의미에서 이번 이슈는 클라우드 이관을 앞두고 있는 시스템이라면 미리 점검해 볼 만한 부분을 확인할 수 있었던 유용한 경험이었습니다.
